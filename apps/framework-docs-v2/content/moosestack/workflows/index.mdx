# Moose Workflows

Moose Workflows adds durable background processing around Moose OLAP. Use it for scheduled jobs, backfills, external calls, or multi-step tasks that should run reliably outside the request path.

<ExportRequirement primitive="Workflow and Task" example="export { myworkflow, prepareReport, persistReport }" />

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/report-workflow.ts" copy
import { Task, Workflow } from "@514labs/moose-lib";

interface ReportRequest {
  reportDate: string;
}

interface ReportResult {
  reportDate: string;
  status: "ready";
}

export const persistReport = new Task<ReportResult, void>("persist_report", {
  run: async (ctx) => {
    console.log(`Persisted report for ${ctx.input.reportDate}`);
  },
});

export const prepareReport = new Task<ReportRequest, ReportResult>("prepare_report", {
  run: async (ctx) => ({
    reportDate: ctx.input.reportDate,
    status: "ready",
  }),
  onComplete: [persistReport],
});

export const myworkflow = new Workflow("daily_report", {
  startingTask: prepareReport,
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/report_workflow.py" copy
from moose_lib import Task, TaskConfig, TaskContext, Workflow, WorkflowConfig
from pydantic import BaseModel

class ReportRequest(BaseModel):
    report_date: str

class ReportResult(BaseModel):
    report_date: str
    status: str

def persist_report(ctx: TaskContext[ReportResult]) -> None:
    print(f"Persisted report for {ctx.input.report_date}")

persist_report_task = Task[ReportResult, None](
    name="persist_report",
    config=TaskConfig(run=persist_report),
)

def prepare_report(ctx: TaskContext[ReportRequest]) -> ReportResult:
    return ReportResult(
        report_date=ctx.input.report_date,
        status="ready",
    )

prepare_report_task = Task[ReportRequest, ReportResult](
    name="prepare_report",
    config=TaskConfig(run=prepare_report, on_complete=[persist_report_task]),
)

myworkflow = Workflow(
    name="daily_report",
    config=WorkflowConfig(starting_task=prepare_report_task),
)
```
  </LanguageTabContent>
</LanguageTabs>

Workflows usually complement other Moose modules rather than replace them. A common pattern is to schedule or trigger work that reads from Moose OLAP, writes new records, or coordinates external systems around your data model.

<Callout type="info" title="Enable workflows before defining them">
Turn on `features.workflows` in `moose.config.toml` before you create `Workflow` and `Task` resources.
</Callout>

```toml filename="moose.config.toml" copy
[features]
workflows = true
```

## What can you do with Moose Workflows?

### Define durable background work

- **[Define workflows](/moosestack/workflows/define-workflow)** with typed tasks and explicit sequencing

### Start work on a schedule or from events

- **[Schedule workflows](/moosestack/workflows/schedule-workflow)** for recurring jobs such as daily refreshes or hourly syncs
- **[Trigger workflows](/moosestack/workflows/trigger-workflow)** from APIs, operators, or other systems

### Control long-running execution

- **[Set retries and timeouts](/moosestack/workflows/retries-and-timeouts)** for failure handling and runtime limits
- **[Cancel running workflows](/moosestack/workflows/cancel-workflow)** when work should stop early
