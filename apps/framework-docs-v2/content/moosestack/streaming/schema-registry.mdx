# Schema registry

<Callout type="info" title="JSON Schema first">
The first supported encoding is JSON Schema. Avro and Protobuf are planned.
</Callout>

Use `schemaConfig` in TypeScript or `schema_config` in Python when a `Stream` should publish using Confluent Schema Registry.

  primitive="Schema Registry stream"
  example="export { events }"

## Configure the Schema Registry URL

Set the Schema Registry URL in `moose.config.toml` under `redpanda_config` or override it with environment variables.

```toml filename="moose.config.toml" copy
[redpanda_config]
broker = "localhost:19092"
schema_registry_url = "http://localhost:8081"
```

Environment overrides (either key works):

```bash filename="Terminal" copy
export MOOSE_REDPANDA_CONFIG__SCHEMA_REGISTRY_URL=http://localhost:8081
# or
export MOOSE_KAFKA_CONFIG__SCHEMA_REGISTRY_URL=http://localhost:8081
```

## Attach Schema Registry config to a stream

You can attach a Schema Registry reference to any `Stream`.

- Use the latest subject version with `{ subjectLatest: string }` in TypeScript or `SubjectLatest(name="...")` in Python.
- Use a specific subject version with `{ subject: string, version: number }` in TypeScript or `SubjectVersion(subject="...", version=...)` in Python.
- Use a fixed schema id with `{ id: number }` in TypeScript or `SchemaById(id=...)` in Python.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="sr-stream.ts" copy
import { Stream, type KafkaSchemaConfig } from "@514labs/moose-lib";

interface Event {
  id: string;
  value: number;
}

const schemaConfig: KafkaSchemaConfig = {
  kind: "JSON",
  reference: { subjectLatest: "event-value" },
};

export const events = new Stream<Event>("events", {
  schemaConfig,
});

// Producing uses Schema Registry envelope automatically
await events.send({ id: "e1", value: 42 });
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="sr_stream.py" copy
from moose_lib import KafkaSchemaConfig, Stream, StreamConfig, SubjectLatest
from pydantic import BaseModel

class Event(BaseModel):
    id: str
    value: int

schema_config = KafkaSchemaConfig(
    kind="JSON",
    reference=SubjectLatest(name="event-value"),
)

events = Stream[Event](
    "events",
    StreamConfig(schema_config=schema_config),
)

events.send(Event(id="e1", value=42))
```
  </LanguageTabContent>
</LanguageTabs>

## Runtime behavior

- If `schemaConfig.kind = "JSON"` or `schema_config.kind = "JSON"` is set, `Stream.send()` publishes records using the Confluent wire format.
- Moose resolves the schema id from the configured reference before sending unless you provide a fixed `id`.
- Moose streaming runners automatically detect the Schema Registry JSON envelope and strip the header before parsing the payload.
- When an [Ingest API](/moosestack/apis/ingest-api) routes to a stream configured this way, Moose also publishes using the Schema Registry envelope.

## Pull existing topics and schemas

Use the CLI to pull external topics and optionally fetch JSON Schemas from Schema Registry to emit typed models.

```bash filename="Terminal" copy
moose kafka pull <bootstrap> \
  --schema-registry http://localhost:8081 \
  --path app/external-topics \
  --include "*" \
  --exclude "{__consumer_offsets,_schemas}"
```

This writes external topic declarations under the provided path based on language (default path is inferred).

## Current limitations

- Only JSON Schema is supported today.
- Avro and Protobuf are not supported yet.
- `schema_registry_url` must be configured before calling `send()` or publishing through an Ingest API to a Schema Registry stream.
- In Python, Schema Registry JSON support requires `confluent-kafka[json,schemaregistry]`.
