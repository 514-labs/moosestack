# Schema registry

<Callout type="info" title="Current support">
Only JSON Schema is supported today. Avro and Protobuf are planned.
</Callout>

Use `schemaConfig` in TypeScript or `schema_config` in Python when a [Stream](/moosestack/streaming/create-stream) should publish through Confluent Schema Registry.

## Requirements

Configure the Schema Registry URL in `moose.config.toml` under `redpanda_config`, or override it with environment variables.

```toml filename="moose.config.toml" copy
[redpanda_config]
broker = "localhost:19092"
schema_registry_url = "http://localhost:8081"
```

Environment overrides (either key works):

```bash filename="Terminal" copy
export MOOSE_REDPANDA_CONFIG__SCHEMA_REGISTRY_URL=http://localhost:8081
# or
export MOOSE_KAFKA_CONFIG__SCHEMA_REGISTRY_URL=http://localhost:8081
```

For Python, install `confluent-kafka[json,schemaregistry]` before publishing to a Schema Registry stream:

```bash filename="Terminal" copy
pip install "confluent-kafka[json,schemaregistry]"
```

## Attach Schema Registry config to a stream

Set `kind` to choose the payload format and `reference` to choose which registered schema Moose uses when it publishes.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="sr-stream.ts" copy
import { Stream, type KafkaSchemaConfig } from "@514labs/moose-lib";

interface Event {
  id: string;
  value: number;
}

const schemaConfig: KafkaSchemaConfig = {
  kind: "JSON",
  reference: { subjectLatest: "event-value" },
};

export const events = new Stream<Event>("events", {
  schemaConfig,
});

// Producing uses Schema Registry envelope automatically
await events.send({ id: "e1", value: 42 });
```
  </LanguageTabContent>
  <LanguageTabContent value="python">

```py filename="sr_stream.py" copy
from moose_lib import KafkaSchemaConfig, Stream, StreamConfig, SubjectLatest
from pydantic import BaseModel

class Event(BaseModel):
    id: str
    value: int

schema_config = KafkaSchemaConfig(
    kind="JSON",
    reference=SubjectLatest(name="event-value"),
)

events = Stream[Event](
    "events",
    StreamConfig(schema_config=schema_config),
)

events.send(Event(id="e1", value=42))
```
  </LanguageTabContent>
</LanguageTabs>

### Kind field

The `kind` field tells Moose which Schema Registry payload format to use for the stream.

- `JSON` publishes records using Schema Registry JSON.
- `JSON` is the only supported value today.

### Reference field

The `reference` field tells Moose how to resolve the schema id before it encodes and publishes a record. Use it to look up the latest version for a subject, pin a specific subject version, or use a fixed schema id directly.

<LanguageTabs>
  <LanguageTabContent value="typescript">
TypeScript reference formats:

<ul>
  <li>Latest subject version: <code>{`{ subjectLatest: string }`}</code> looks up the newest schema version registered under that subject.</li>
  <li>Specific subject version: <code>{`{ subject: string, version: number }`}</code> pins publishing to one subject version.</li>
  <li>Fixed schema id: <code>{`{ id: number }`}</code> uses a known schema id directly.</li>
</ul>
  </LanguageTabContent>
  <LanguageTabContent value="python">
Python reference formats:

<ul>
  <li>Latest subject version: <code>SubjectLatest(name="...")</code> looks up the newest schema version registered under that subject.</li>
  <li>Specific subject version: <code>SubjectVersion(subject="...", version=...)</code> pins publishing to one subject version.</li>
  <li>Fixed schema id: <code>SchemaById(id=...)</code> uses a known schema id directly.</li>
</ul>
  </LanguageTabContent>
</LanguageTabs>

## Runtime behavior

- If `schemaConfig.kind = "JSON"` or `schema_config.kind = "JSON"` is set, [`Stream.send()`](/moosestack/streaming/from-your-code) publishes records using the Confluent wire format.
- Moose resolves the schema id from the configured reference before sending unless you provide a fixed `id`.
- Moose streaming runners automatically detect the Schema Registry JSON envelope and strip the header before parsing the payload.
- When an [Ingest API](/moosestack/apis/ingest-api) routes to a stream configured this way, Moose also publishes using the Schema Registry envelope.
- Publishing fails if `schema_registry_url` is not configured.

## Pull existing topics and schemas

Use the CLI to pull external topics and optionally fetch JSON Schemas from Schema Registry to emit typed models.

```bash filename="Terminal" copy
moose kafka pull <bootstrap> \
  --schema-registry http://localhost:8081 \
  --path app/external-topics \
  --include "*" \
  --exclude "{__consumer_offsets,_schemas}"
```

This writes external topic declarations under the provided path. When Schema Registry subjects are available, Moose also emits typed models from the fetched JSON Schemas.
