# Moose Streams
Moose Streams adds continuous ingest and event processing around Moose OLAP. Use it when data arrives continuously, needs to be transformed before storage, or should land in ClickHouse tables through managed stream pipelines backed by Kafka or Redpanda.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/stream.ts" copy
import { Stream } from "@514labs/moose-lib";
import { table } from "./table";

interface Record {
  id: string;
  name: string;
  timestamp: Date;
}

export const stream = new Stream<Record>("stream", {
  destination: table,
  version: "0.0",
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/stream.py" copy
from datetime import datetime

from moose_lib import Stream, StreamConfig
from app.table import table
from pydantic import BaseModel

class Record(BaseModel):
    id: str
    name: str
    timestamp: datetime

stream = Stream[Record]("stream", config=StreamConfig(
    destination=table,
    version="0.0",
))
```
  </LanguageTabContent>
</LanguageTabs>

Most Moose projects start by defining an OLAP table, then attach a stream when they need continuous ingest or real-time processing before data becomes queryable in ClickHouse.

<Callout type="info" title="Enable Moose Streams before defining streams">
Turn on `features.streaming_engine` in `moose.config.toml` before you create stream resources or attach them to OLAP tables.
</Callout>

```toml filename="moose.config.toml"
[features]
streaming_engine = true
```

## What can you do with Moose Streams?

### Define streams

- **[Define a stream](/moosestack/streaming/create-stream)** with a typed payload backed by a Kafka or Redpanda topic

### Send records

- **[Publish from Moose code with `Stream.send()`](/moosestack/streaming/from-your-code)** for in-process producers
- **[Publish from external systems with the Ingest API](/moosestack/apis/ingest-api)** for HTTP-based ingestion
- **[Use Schema registry](/moosestack/streaming/schema-registry)** when stream payloads should use Confluent Schema Registry

### Process records

- **[Run consumer functions](/moosestack/streaming/consumer-functions)** when records should trigger side effects
- **[Run transform functions](/moosestack/streaming/transform-functions)** when records should be filtered, enriched, or rewritten into another stream
- **[Use stream patterns](/moosestack/streaming/stream-patterns)** for fan-in, fan-out, and chained processing flows

### Land records in ClickHouse

- **[Sync to table](/moosestack/streaming/sync-to-table)** when stream records should land in Moose OLAP tables

### Recover failures

- **[Use dead letter queues](/moosestack/streaming/dead-letter-queues)** when failed records should be retained for recovery
