# Dead letter queues

Use `DeadLetterQueue<T>` to capture records of type `T` that fail during stream processing. A dead letter queue is itself a stream of wrapper records: Moose keeps the original payload and adds error details about why that record failed.

<ExportRequirement
  primitive="dead letter queue"
  example="export { userEventDLQ }"
  pythonExample="from app.dead_letter_queue import user_event_dlq"
/>

## When records are written here

Records are written to a dead letter queue when a configured stream component fails while handling them.

- A transform throws while processing a record.
- A consumer throws while processing a record.
- An [Ingest API](/moosestack/apis/ingest-api) is configured with a dead letter queue and cannot process a record cleanly.

## Create a dead letter queue

<LanguageTabs>
  <LanguageTabContent value="typescript">

```ts filename="app/dead-letter-queue.ts" copy
import { DeadLetterQueue } from "@514labs/moose-lib";

interface UserEvent {
  userId: string;
  action: string;
  timestamp: Date;

const userEventDLQ = new DeadLetterQueue<UserEvent>("user_event_dlq");
```

## Attach to a transform

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/transform-with-dlq.ts" copy
import { DeadLetterQueue, Stream } from "@514labs/moose-lib";

interface RawRecord {
  id: string;
  name: str;
  timestamp: Date;
}

interface ProcessedRecord extends RawRecord {
  processed: Date;
}

const rawRecords = new Stream<RawRecord>("raw_records");
const processedRecords = new Stream<ProcessedRecord>("processed_records");
const recordDLQ = new DeadLetterQueue<RawRecord>("record_dlq");

rawEvents.addTransform(
  processedEvents,
  (record) => {
    if (!record.id) {
      throw new Error("Invalid id");
    }

    return {
      id: record.id,
      name: record.name,
      processed: new Date(),
    };
  },
  {
    deadLetterQueue: recordDLQ,
  }
);
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/transform_with_dlq.py" copy
from moose_lib import DeadLetterQueue, Stream, TransformConfig
from pydantic import BaseModel
from datetime import datetime

class RawRecord(BaseModel):
    id: str
    name: str
    timestamp: datetime

class ProcessedRecord(BaseModel):
    id: str
    name: str
    processed: datetime

raw_records = Stream[RawRecord]("raw_records")
processed_records = Stream[ProcessedRecord]("processed_records")
record_dlq = DeadLetterQueue[RawRecord]("record_dlq")

def process_record(record: RawRecord) -> ProcessedRecord:
    if not record.id:
        raise ValueError("Invalid id")

    return ProcessedRecord(
        id=record.id,
        name=record.name,
        processed=datetime.now(),
    )

raw_records.add_transform(
    destination=processed_records,
    transformation=process_record,
    config=TransformConfig(dead_letter_queue=record_dlq),
)
```
  </LanguageTabContent>
</LanguageTabs>

## Attach to a consumer

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/consumer-with-dlq.ts" copy
import { ConsumerConfig, DeadLetterQueue, Stream } from "@514labs/moose-lib";

interface RawEvent {
  userId: string;
  action: string;
}

const rawEvents = new Stream<RawEvent>("raw_events");
const eventDLQ = new DeadLetterQueue<RawEvent>("event_dlq");

rawEvents.addConsumer(
  (event) => {
    if (event.action === "forbidden_action") {
      throw new Error("Forbidden action detected");
    }

    console.log(`Processing ${event.action} for ${event.userId}`);
  },
  {
    deadLetterQueue: eventDLQ,
  } satisfies ConsumerConfig<RawEvent>
);
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/consumer_with_dlq.py" copy
from moose_lib import ConsumerConfig, DeadLetterQueue, Stream
from pydantic import BaseModel

class RawEvent(BaseModel):
    user_id: str
    action: str

raw_events = Stream[RawEvent]("raw_events")
event_dlq = DeadLetterQueue[RawEvent]("event_dlq")

def process_event_consumer(event: RawEvent) -> None:
    if event.action == "forbidden_action":
        raise ValueError("Forbidden action detected")

    print(f"Processing {event.action} for {event.user_id}")

raw_events.add_consumer(
    consumer=process_event_consumer,
    config=ConsumerConfig(dead_letter_queue=event_dlq),
)
```
  </LanguageTabContent>
</LanguageTabs>

## Dead letter record shape

Each dead letter queue entry stores the original failed payload plus these augmented fields:

- the original record
- the error message
- the error type
- when the failure happened
- the failure source, such as `transform` or `api`

When Moose writes a failed record into a dead letter queue, it wraps the original payload with this shape.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/dead-letter-types.ts" copy
interface DeadLetterModel {
  originalRecord: Record<string, any>;
  errorMessage: string;
  errorType: string;
  failedAt: Date;
  source: "api" | "transform" | "table";
}

interface DeadLetter<T> extends DeadLetterModel {
  asTyped: () => T;
}
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/dead_letter_types.py" copy
from datetime import datetime
from typing import Any, Generic, Literal, TypeVar

from pydantic import BaseModel

T = TypeVar("T")

class DeadLetterModel(BaseModel, Generic[T]):
    original_record: Any
    error_message: str
    error_type: str
    failed_at: datetime
    source: Literal["api", "transform", "table"]

    def as_typed(self) -> T:
        ...
```
  </LanguageTabContent>
</LanguageTabs>

The original failed payload stays under `originalRecord` in TypeScript or `original_record` in Python. Moose adds the error fields and timestamp when it writes the dead letter.

Use `asTyped()` in TypeScript or `as_typed()` in Python to recover the original typed record from the dead letter payload.

## Inspect or recover dead letters

Because a dead letter queue is itself a stream, you can attach consumers or transforms to it for monitoring or recovery.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/dlq-recovery.ts" copy
import { DeadLetterQueue } from "@514labs/moose-lib";

interface UserEvent {
  userId: string;
  action: string;
}

const eventDLQ = new DeadLetterQueue<UserEvent>("event_dlq");

eventDLQ.addConsumer((deadLetter) => {
  console.error(deadLetter.errorMessage);
  const originalEvent = deadLetter.asTyped();
  console.log(originalEvent.userId);
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/dlq_recovery.py" copy
from moose_lib import DeadLetterQueue
from pydantic import BaseModel

class UserEvent(BaseModel):
    user_id: str
    action: str

event_dlq = DeadLetterQueue[UserEvent]("event_dlq")

def monitor_dead_letters(dead_letter) -> None:
    print(dead_letter.error_message)
    original_event = dead_letter.as_typed()
    print(original_event.user_id)

event_dlq.add_consumer(monitor_dead_letters)
```
  </LanguageTabContent>
</LanguageTabs>

<Callout type="info" title="Dead letter queues are for recovery, not silent drops">
Use a dead letter queue when failures should be retained for inspection or replay instead of disappearing from the stream pipeline.
</Callout>
