# Sync to table

Use the `destination` option on a `Stream` when records from that stream should be batched and written into an OLAP table automatically.

This page covers the sync behavior after you set `destination`. To define the `Stream` itself, start with [Stream](/moosestack/streaming/create-stream).

## Basic usage

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/stream.ts" copy
import { OlapTable, Stream } from "@514labs/moose-lib";

interface Record {
  id: string;
  name: string;
  timestamp: Date;
  type: "foo" | "bar";
}

const table = new OlapTable<Record>("table");

const stream = new Stream<Record>("stream", {
  destination: table,
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/stream.py" copy
from datetime import datetime
from typing import Literal

from moose_lib import OlapTable, Stream, StreamConfig
from pydantic import BaseModel

class Record(BaseModel):
    id: str
    name: str
    timestamp: datetime
    type: Literal["foo", "bar"]

table = OlapTable[Record]("table")

stream = Stream[Record]("stream", StreamConfig(
    destination=table,
))
```
  </LanguageTabContent>
</LanguageTabs>

## What happens after you set `destination`

- Moose starts a background sync worker that reads from the stream topic and inserts records into the destination table in ClickHouse.
- Records are not queryable as soon as they enter the stream. They become queryable only after a batch insert succeeds.

## Current runtime behavior

<table>
  <thead>
    <tr>
      <th>Behavior</th>
      <th>Current behavior</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Batch flush trigger</td>
      <td>Moose flushes when a batch reaches <code>100000</code> records or when the 1 second flush interval ticks.</td>
    </tr>
    <tr>
      <td>Query visibility</td>
      <td>Rows become queryable only after the destination table receives a successful batch insert.</td>
    </tr>
    <tr>
      <td>Failed inserts</td>
      <td>If a ClickHouse insert fails, the batch stays queued and Moose retries it on later flush attempts.</td>
    </tr>
    <tr>
      <td>Delivery guarantee</td>
      <td>Delivery is at least once. Moose stores stream offsets after a batch insert succeeds.</td>
    </tr>
  </tbody>
</table>

## Destination requirements

- `destination` must point at an `OlapTable` instance.
- The destination table schema must match the stream schema.
- If you need to define the table first, start with [Model Table](/moosestack/olap/model-table).
