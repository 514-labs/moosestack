# Model table

Use `OlapTable<T>` or `OlapTable[Model]` to define a typed ClickHouse table in your Moose project. The model shape becomes the table schema, and the table object becomes the resource you query, insert into, use as a stream destination, or target from materialized views.

<Callout type="info" title="Enable OLAP before defining tables">
Turn on `features.olap` in `moose.config.toml` before creating OLAP tables.
</Callout>

  primitive="table"
  example="export { table }"
  pythonExample="from app.table import table"

## Basic usage

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/table.ts" copy
import { Key, OlapTable } from "@514labs/moose-lib";

interface Record {
  id: Key<string>;
  name: string;
  timestamp: Date;
}

export const table = new OlapTable<Record>("table");
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/table.py" copy
from datetime import datetime

from moose_lib import Key, OlapTable
from pydantic import BaseModel

class Record(BaseModel):
    id: Key[str]
    name: str
    timestamp: datetime

table = OlapTable[Record]("table")
```
  </LanguageTabContent>
</LanguageTabs>

If you do not specify an engine, Moose creates the table with the default `MergeTree` engine. `Key` in TypeScript and `Key[...]` in Python mark fields Moose should treat as part of the inferred primary key unless you override that behavior with a custom primary-key expression.

## Example configuration

Use table config when you need to control ordering, versioning, partitioning, lifecycle behavior, or a non-default engine.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/table.ts" copy
import {
  ClickHouseEngines,
  Key,
  LifeCycle,
  OlapTable,
} from "@514labs/moose-lib";

interface EventRecord {
  id: Key<string>;
  userId: string;
  timestamp: Date;
  updatedAt: Date;
}

export const events = new OlapTable<EventRecord>("events", {
  engine: ClickHouseEngines.ReplacingMergeTree,
  orderByFields: ["userId", "timestamp", "id"],
  partitionBy: "toYYYYMM(timestamp)",
  ver: "updatedAt",
  version: "1.0",
  lifeCycle: LifeCycle.FULLY_MANAGED,
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/table.py" copy
from datetime import datetime

from moose_lib import Key, LifeCycle, OlapConfig, OlapTable, ReplacingMergeTreeEngine
from pydantic import BaseModel

class EventRecord(BaseModel):
    id: Key[str]
    user_id: str
    timestamp: datetime
    updated_at: datetime

events = OlapTable[EventRecord]("events", config=OlapConfig(
    engine=ReplacingMergeTreeEngine(ver="updated_at"),
    order_by_fields=["user_id", "timestamp", "id"],
    partition_by="toYYYYMM(timestamp)",
    version="1.0",
    life_cycle=LifeCycle.FULLY_MANAGED,
))
```
  </LanguageTabContent>
</LanguageTabs>

<Callout type="info" title="Python engine config classes are preferred">
Use engine config classes such as `MergeTreeEngine()` or `ReplacingMergeTreeEngine(...)` in Python. The `ClickHouseEngines` enum still works for backward compatibility, but it emits a deprecation warning.
</Callout>

## Behavior and edge cases

<table>
  <thead>
    <tr>
      <th>Behavior</th>
      <th>Current behavior</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Default engine</td>
      <td>If you omit <code>engine</code>, Moose creates the table with the default <code>MergeTree</code> engine.</td>
    </tr>
    <tr>
      <td>Inferred primary key</td>
      <td><code>Key</code> in TypeScript and <code>Key[...]</code> in Python mark fields Moose should infer as primary-key columns unless you set <code>primaryKeyExpression</code> or <code>primary_key_expression</code>.</td>
    </tr>
    <tr>
      <td>Versioned table names</td>
      <td>If you set <code>version</code>, Moose appends that version to the physical table name. For example, <code>"events"</code> with version <code>"1.0"</code> becomes <code>events_1_0</code>.</td>
    </tr>
    <tr>
      <td>Ordering config</td>
      <td>Use either <code>orderByFields</code> or <code>orderByExpression</code> in TypeScript, and either <code>order_by_fields</code> or <code>order_by_expression</code> in Python. Do not set both.</td>
    </tr>
    <tr>
      <td>Optional fields with defaults</td>
      <td>If a field is optional in your app model but also has a ClickHouse default annotation, Moose keeps it optional at the app layer while generating a non-nullable ClickHouse column with a <code>DEFAULT</code> clause.</td>
    </tr>
    <tr>
      <td>Column comments</td>
      <td>TypeScript TSDoc comments and Python <code>Field(description=...)</code> or attribute docstrings become ClickHouse column <code>COMMENT</code> clauses.</td>
    </tr>
    <tr>
      <td>Engine-specific clauses</td>
      <td>Some engines do not support clauses such as <code>ORDER BY</code>, <code>PARTITION BY</code>, <code>SAMPLE BY</code>, or projections. Match the config fields you set to the capabilities of the chosen engine.</td>
    </tr>
    <tr>
      <td>Database-qualified names</td>
      <td>If you set <code>database</code>, Moose qualifies the table as <code>`database`.`table_name`</code> when it renders SQL references.</td>
    </tr>
  </tbody>
</table>

## ReplacingMergeTree example

Use `ReplacingMergeTree` when later rows should replace earlier rows that share the same sorting key.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/table.ts" copy
import {
  ClickHouseEngines,
  Key,
  OlapTable,
} from "@514labs/moose-lib";

interface UserSnapshot {
  id: Key<string>;
  email: string;
  updatedAt: Date;
  deleted: 0 | 1;
}

export const users = new OlapTable<UserSnapshot>("users", {
  engine: ClickHouseEngines.ReplacingMergeTree,
  orderByFields: ["id"],
  ver: "updatedAt",
  isDeleted: "deleted",
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/table.py" copy
from datetime import datetime

from moose_lib import Key, OlapConfig, OlapTable, ReplacingMergeTreeEngine
from pydantic import BaseModel

class UserSnapshot(BaseModel):
    id: Key[str]
    email: str
    updated_at: datetime
    deleted: int

users = OlapTable[UserSnapshot]("users", config=OlapConfig(
    engine=ReplacingMergeTreeEngine(
        ver="updated_at",
        is_deleted="deleted",
    ),
    order_by_fields=["id"],
))
```
  </LanguageTabContent>
</LanguageTabs>

`isDeleted` in TypeScript and `is_deleted` in Python require a version column as well.
