# Insert data

Use `OlapTable.insert()` for direct writes into ClickHouse tables from app code, scripts, workflows, or backfills. This page focuses on direct OLAP inserts. If you need event-at-a-time ingestion or external producers, use the routing table below and follow the owning page for that path.

## Choose an insert path

<table>
  <thead>
    <tr>
      <th>Path</th>
      <th>Use it when</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>table.insert()</code></td>
      <td>You already have records in application code and want to write batches directly into ClickHouse.</td>
    </tr>
    <tr>
      <td><a href="/moosestack/streaming/create-stream"><code>Stream</code> with a destination table</a></td>
      <td>You want record-at-a-time ingestion inside Moose and automatic batching from the stream into ClickHouse.</td>
    </tr>
    <tr>
      <td><a href="/moosestack/apis/ingest-api"><code>IngestApi</code></a></td>
      <td>An external system should send records over HTTP instead of importing Moose objects directly.</td>
    </tr>
    <tr>
      <td><a href="/moosestack/workflows"><code>Workflow</code></a></td>
      <td>You need orchestration, retries, or scheduled batch jobs that eventually call <code>insert()</code>.</td>
    </tr>
  </tbody>
</table>

<Callout type="info" title="ClickHouse prefers batches">
Single-record inserts work, but ClickHouse performs best with batches. If your producer naturally emits one event at a time, prefer a [Stream](/moosestack/streaming/create-stream) or [Ingest API](/moosestack/apis/ingest-api) instead of calling `insert()` for each record.
</Callout>

<Callout type="info" title="Computed columns are excluded from inserts">
[Alias columns](/moosestack/olap/alias-columns) and [materialized columns](/moosestack/olap/materialized-columns) are omitted automatically from direct inserts. In TypeScript, `insert()` accepts `Insertable<T>[]`, which excludes computed columns and makes defaulted columns optional. In Python, fields annotated with `ClickHouseAlias` or `ClickHouseMaterialized` can be omitted from inserted records.
</Callout>

## Basic usage

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/insert.ts" copy
import { table } from "./table";

const result = await table.insert([
  {
    id: "evt_1",
    name: "signup",
    timestamp: new Date(),
  },
  {
    id: "evt_2",
    name: "purchase",
    timestamp: new Date(),
  },
]);

console.log(result.successful);
console.log(result.failed);
```

## Handle partial failures

Use discard mode when you want good records to continue through while bad records are dropped within configured thresholds.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/insert.ts" copy
import { table } from "./table";

const result = await table.insert(data, {
  strategy: "discard",
  allowErrors: 10,
  allowErrorsRatio: 0.05,
});

console.log(result.failedRecords);
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/insert.py" copy
from moose_lib import InsertOptions

from app.table import table

result = table.insert(
    data,
    options=InsertOptions(
        strategy="discard",
        allow_errors=10,
        allow_errors_ratio=0.05,
    ),
)

print(result.failed_records)
```
  </LanguageTabContent>
</LanguageTabs>

Use isolate mode when you want Moose to retry smaller batches and then individual records to identify exactly which records failed.

## Stream or generator input

For large direct inserts, you can stream records instead of materializing a full array in memory.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/insert.ts" copy
import { Readable } from "node:stream";

import { table } from "./table";

const dataStream = Readable.from([
  { id: "evt_1", name: "signup", timestamp: new Date() },
  { id: "evt_2", name: "purchase", timestamp: new Date() },
]);

const result = await table.insert(dataStream, {
  strategy: "fail-fast",
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/insert.py" copy
from datetime import datetime

from moose_lib import InsertOptions

from app.table import table

def event_stream():
    yield {"id": "evt_1", "name": "signup", "timestamp": datetime.now()}
    yield {"id": "evt_2", "name": "purchase", "timestamp": datetime.now()}

result = table.insert(
    event_stream(),
    options=InsertOptions(strategy="fail-fast"),
)
```
  </LanguageTabContent>
</LanguageTabs>

Validation is not available for stream or generator input, and isolate mode is not supported there.

## Insert behavior

<table>
  <thead>
    <tr>
      <th>Behavior</th>
      <th>Current behavior</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Computed columns</td>
      <td>Alias and materialized columns are excluded automatically from direct inserts.</td>
    </tr>
    <tr>
      <td>Defaulted columns</td>
      <td>Columns with ClickHouse defaults can be omitted from inserted records.</td>
    </tr>
    <tr>
      <td>Stream or generator input</td>
      <td>Validation is skipped for streaming input, and Moose does not report per-record counts for successful streamed inserts.</td>
    </tr>
    <tr>
      <td><code>isolate</code> strategy</td>
      <td>Supported for array or list input only. It is not available for stream or generator input.</td>
    </tr>
    <tr>
      <td>Discard thresholds</td>
      <td><code>allowErrors</code> and <code>allowErrorsRatio</code> only matter when using discard mode.</td>
    </tr>
  </tbody>
</table>
