# Moose OLAP

Moose OLAP is MooseStack's schema-as-code layer for ClickHouse. It turns tables, views, and materialized views into typed objects your app can read from, write to, and evolve in code.

<LanguageTabs>
  <LanguageTabContent value="typescript">
```ts filename="app/table.ts"
import { OlapTable, ClickHouseEngines, LifeCycle } from "@514labs/moose-lib";

interface Record {
  id: string;
  name: string;
  timestamp: Date;
}

export const table = new OlapTable<Record>("table", {
  engine: ClickHouseEngines.MergeTree,
  orderByFields: ["id"],
  version: "0.0",
  lifeCycle: LifeCycle.FULLY_MANAGED,
});
```
  </LanguageTabContent>
  <LanguageTabContent value="python">
```py filename="app/table.py"
from datetime import datetime

from moose_lib import ClickHouseEngines, LifeCycle, OlapConfig, OlapTable
from pydantic import BaseModel

class Record(BaseModel):
    id: str
    name: str
    timestamp: datetime

table = OlapTable[Record]("table", config=OlapConfig(
  engine=ClickHouseEngines.MergeTree,
  order_by_fields=["id"],
  version="0.0",
  life_cycle=LifeCycle.FULLY_MANAGED,
))
```
  </LanguageTabContent>
</LanguageTabs>

## Evolve or adopt an existing schema

- Carry local schema changes forward to staging and production environments with [schema migrations](/moosestack/olap/apply-migrations) during development and [planned migrations](/moosestack/olap/planned-migrations) for remote environments
- [Work with existing ClickHouse tables](/moosestack/olap/external-tables) and [pull those schemas into your project](/moosestack/olap/db-pull) when Moose is not the only system managing them

## Read and write data

- [Query data](/moosestack/olap/read-data) from your application code or APIs through typed table and view objects
- [Insert data](/moosestack/olap/insert-data) for ingestion flows, backfills, or batch writes
