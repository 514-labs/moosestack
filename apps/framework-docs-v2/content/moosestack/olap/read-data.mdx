# Read data

Use this page when you need to run a query against an [`OlapTable`](/moosestack/olap/model-table) or [`MaterializedView`](/moosestack/olap/model-materialized-view) from application code. It covers query client setup, query methods, TypeScript SQL helpers, and the Python query builder.

## Query client

<LanguageTabs>
  <LanguageTabContent value="typescript">
### Get a query client

Use `getMooseUtils()` to get both `client` and `sql`. Use the same helper inside Moose runtime handlers and standalone TypeScript code. For framework-specific setup, see [Express](/moosestack/app-api-frameworks/express).

```ts filename="app/query.ts" copy
import { getMooseUtils } from "@514labs/moose-lib";

const { client, sql } = await getMooseUtils();
```

`getMooseUtils()` reads ClickHouse connection details from these environment variables in both runtime and standalone use. If you're using the Moose client outside the Moose runtime, make sure these values are set in that environment:

```bash title=".env" copy
MOOSE_CLICKHOUSE_CONFIG__HOST=localhost
MOOSE_CLICKHOUSE_CONFIG__HOST_PORT=18123
MOOSE_CLICKHOUSE_CONFIG__USER=panda
MOOSE_CLICKHOUSE_CONFIG__PASSWORD=pandapass
MOOSE_CLICKHOUSE_CONFIG__DB_NAME=local
MOOSE_CLICKHOUSE_CONFIG__USE_SSL=false
```

`getMooseUtils()` is async. Always await it before accessing `client` or `sql`.

### Execute queries

Use `client.query.execute()` with a `sql.statement` query when you are reading from Moose OLAP in TypeScript.

```ts filename="app/query.ts" copy
import { getMooseUtils } from "@514labs/moose-lib";

import { table } from "./table";

const { client, sql } = await getMooseUtils();

const result = await client.query.execute(sql.statement`
  SELECT
    ${table.columns.id},
    ${table.columns.name}
  FROM ${table}
  LIMIT ${10}
`);

const rows = await result.json();
```

This method returns a ClickHouse JSONEachRow result set. Read rows with `await result.json()`. In TypeScript, read queries go through `client.query.execute(...)`; change how you construct the SQL with `sql.statement`, `sql.fragment`, and `sql.join`, not by switching to a different read method.

### Get a query client

Use `QueryClient(config_registry.get_clickhouse_config())` for standalone access to ClickHouse from Python code. For framework-specific setup, see [FastAPI](/moosestack/app-api-frameworks/fastapi).

```py filename="app/query.py" copy
from moose_lib import QueryClient, config_registry

query_client = QueryClient(config_registry.get_clickhouse_config())
```

### Write type-safe, interpolated queries

Use `query_client.execute(...)` when you want Moose-managed interpolation for table objects, column objects, and scalar parameters, or when you want to pass a typed `Query` builder object instead of raw SQL text.

Use a SQL string when you want to write the query directly:

```py filename="app/query.py" copy
from moose_lib import QueryClient, config_registry

from app.table import table

query_client = QueryClient(config_registry.get_clickhouse_config())

query = """
  SELECT
    {id_column},
    {name_column}
  FROM {table}
  WHERE {name_column} = {name}
  LIMIT {limit}
"""

rows = query_client.execute(query, {
    "id_column": table.cols.id,
    "name_column": table.cols.name,
    "table": table,
    "name": "signup",
    "limit": 10,
})
```

`execute()` is Python's interpolation surface. It treats Moose [`OlapTable`](/moosestack/olap/model-table) and column objects as identifiers instead of scalar values. If the table has a `database` config in its [table definition](/moosestack/olap/model-table), Moose automatically qualifies it in generated SQL.

Use the materialized-view target table when you want interpolation to follow the stored table shape, including target-table columns exposed through Moose models:

```py filename="app/query.py" copy
from moose_lib import QueryClient, config_registry

from app.materialized_view import daily_stats

query_client = QueryClient(config_registry.get_clickhouse_config())

query = """
  SELECT
    {day_column},
    sumMerge(total_views) AS total_views
  FROM {table}
  WHERE {day_column} >= {since}
  GROUP BY {day_column}
"""

rows = query_client.execute(query, {
    "day_column": daily_stats.target_table.cols.day,
    "table": daily_stats.target_table,
    "since": "2026-01-01",
})
```

In Python, write the merge function explicitly in SQL when the target table stores aggregate states.

Pass `row_type` when you want rows mapped into a Pydantic model:

```py filename="app/query.py" copy
from pydantic import BaseModel
from moose_lib import QueryClient, config_registry

from app.table import table

class EventRow(BaseModel):
    id: str
    name: str

query_client = QueryClient(config_registry.get_clickhouse_config())

rows = query_client.execute(
    """
      SELECT id, name
      FROM {table}
      LIMIT {limit}
    """,
    {
        "table": table,
        "limit": 10,
    },
    row_type=EventRow,
)
```

Use a `Query` object when you want a structured builder instead of writing SQL directly:

```py filename="app/query.py" copy
from moose_lib import QueryClient, config_registry
from moose_lib.query_builder import Query, col

from app.table import table

query_client = QueryClient(config_registry.get_clickhouse_config())

query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .where(col(table.cols.name).eq("signup"))
    .limit(10)
)

rows = query_client.execute(query)
```

**Reference**

| Input form | Call shape | Returns |
| --- | --- | --- |
| SQL string | `query_client.execute(sql_string, variables, row_type=None)` | A list of row dicts by default, or a list of `row_type` instances when provided |
| Query builder | `query_client.execute(query_builder, row_type=None)` | A list of row dicts by default, or a list of `row_type` instances when provided |

### Write raw SQL queries

Use `query_client.execute_raw(clickhouse_query, parameters, row_type=None)` when you want full control over the SQL text and parameter types instead of Moose-managed interpolation.

```py filename="app/query.py" copy
from moose_lib import QueryClient, config_registry

query_client = QueryClient(config_registry.get_clickhouse_config())

query = """
  SELECT id, name
  FROM {table: Identifier}
  WHERE name = {name:String}
  LIMIT {limit:UInt32}
"""

rows = query_client.execute_raw(query, {
    "table": "events",
    "name": "signup",
    "limit": 10,
})
```

**Reference**

| Call shape | Use it for | Returns |
| --- | --- | --- |
| `query_client.execute_raw(clickhouse_query, parameters, row_type=None)` | Raw ClickHouse SQL with explicit parameter typing | A list of row dicts by default, or a list of `row_type` instances when provided |

Use typed placeholders such as <code>{"{limit:UInt32}"}</code> and <code>{"{table: Identifier}"}</code> when ClickHouse needs explicit parameter types.

## SQL helpers

Use the `sql` tag helpers when you want structured TypeScript query construction without switching to a separate query-builder API.

The snippets below assume `sql` and `table` are already imported.

### sql.statement

Use `sql.statement` for complete SQL statements such as `SELECT` queries.

```ts filename="app/query.ts" copy
const query = sql.statement`
  SELECT
    ${table.columns.id},
    ${table.columns.name}
  FROM ${table}
  WHERE ${table.columns.name} = ${"signup"}
  ORDER BY ${table.columns.id}
`;
```

### sql.fragment

Use `sql.fragment` for reusable partial SQL such as predicates, expressions, and clause fragments.

```ts filename="app/query.ts" copy
const nameFilter = sql.fragment`${table.columns.name} ILIKE ${"%moose%"}`;

const query = sql.statement`
  SELECT * FROM ${table}
  WHERE ${nameFilter}
`;
```

### sql.join

Use `sql.join` to combine multiple SQL fragments with a separator.

```ts filename="app/query.ts" copy
const conditions = [
  sql.fragment`${table.columns.name} ILIKE ${"%moose%"}`,
  sql.fragment`${table.columns.id} != ${"system"}`,
];

const query = sql.statement`
  SELECT * FROM ${table}
  WHERE ${sql.join(conditions, " AND ")}
`;
```

### sql.raw

Use `sql.raw` only when you need trusted static SQL text that should not be parameterized or escaped.

```ts filename="app/query.ts" copy
const direction = sql.raw("DESC");

const query = sql.statement`
  SELECT
    ${table.columns.id},
    ${table.columns.name}
  FROM ${table}
  ORDER BY ${table.columns.id} ${direction}
`;
```

The bare `sql` template tag still exists for backward compatibility, but `sql.statement` and `sql.fragment` are the preferred forms.

### Interpolate tables and columns

Use Moose table and column objects when you want identifier-safe SQL that follows the current table definition. For how those table objects are modeled, see [Model table](/moosestack/olap/model-table).

```ts filename="app/query.ts" copy
import { getMooseUtils } from "@514labs/moose-lib";

import { table } from "./table";

const { client, sql } = await getMooseUtils();

const query = sql.statement`
  SELECT
    ${table.columns.id},
    ${table.columns.name}
  FROM ${table}
  WHERE ${table.columns.id} = ${"user_123"}
`;

const result = await client.query.execute(query);
```

If the table has a `database` config in its [table definition](/moosestack/olap/model-table), Moose automatically qualifies it as `` `database`.`table_name` `` in generated SQL.

For materialized views, use the target table when you want interpolation to follow the stored table shape instead of treating the materialized-view definition as a generic string reference.

```ts filename="app/query.ts" copy
import { getMooseUtils } from "@514labs/moose-lib";

import { dailyStats } from "./materialized-view";

const { client, sql } = await getMooseUtils();

const query = sql.statement`
  SELECT
    ${dailyStats.targetTable.columns.day},
    ${dailyStats.targetTable.columns.totalViews}
  FROM ${dailyStats.targetTable}
  WHERE ${dailyStats.targetTable.columns.day} >= ${"2026-01-01"}
`;

const result = await client.query.execute(query);
```

When a TypeScript materialized-view target table stores `AggregateFunction` columns, Moose expands the correct merge function when you interpolate the column through `sql.statement`.

## Query builder

Use `Query()` when you want a structured alternative to formatter-style SQL strings and still execute the finished query with `query_client.execute(query)`.

```py filename="app/query.py" copy
from moose_lib import QueryClient, config_registry
from moose_lib.query_builder import Query, col

from app.table import table

query_client = QueryClient(config_registry.get_clickhouse_config())

query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .where(col(table.cols.name).eq("signup"))
    .order_by((table.cols.id, "desc"))
    .limit(10)
)

rows = query_client.execute(query)
```

The snippets below assume `Query`, `col`, `and_`, `or_`, and `table` are already imported.

### from_()

Use `from_()` to set the source table for the query.

```py filename="app/query.py" copy
query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
)
```

### select()

Use `select()` to choose the Moose columns you want returned.

```py filename="app/query.py" copy
query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
)
```

### where()

Use `where()` to apply a filter predicate or SQL expression.

```py filename="app/query.py" copy
query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .where(col(table.cols.name).eq("signup"))
)
```

Use `and_()` when every grouped predicate must be true.

```py filename="app/query.py" copy
from moose_lib.query_builder import Query, and_, col

query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .where(
        and_(
            col(table.cols.name).eq("signup"),
            col(table.cols.id).ne("system"),
        )
    )
)
```

</TabsContent>
<TabsContent value="or">

Use `or_()` when any one of the grouped predicates can match.

```py filename="app/query.py" copy
from moose_lib.query_builder import Query, col, or_

query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .where(
        or_(
            col(table.cols.name).eq("signup"),
            col(table.cols.name).eq("purchase"),
        )
    )
)
```

### order_by()

Use `order_by()` to sort by columns or `(column, "asc" | "desc")` tuples.

```py filename="app/query.py" copy
query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .order_by((table.cols.id, "desc"))
)
```

### limit()

Use `limit()` to cap the number of returned rows.

```py filename="app/query.py" copy
query = (
    Query()
    .from_(table)
    .select(table.cols.id, table.cols.name)
    .limit(10)
)
```

For debugging or inspection, `query.to_sql()` returns the generated ClickHouse SQL and `query.to_sql_and_params()` returns the SQL plus bound parameters.

| --- | --- |
| `SELECT *` | Moose includes ClickHouse [materialized columns](/moosestack/olap/materialized-columns) and [alias columns](/moosestack/olap/alias-columns) when a query uses `*`. |
