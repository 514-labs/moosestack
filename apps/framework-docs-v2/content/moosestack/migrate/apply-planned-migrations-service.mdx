# moose prod (Runtime)

`moose prod` runs the full Moose server. As part of its boot sequence, it automatically applies any committed migration files that have not yet been run against the target database. Use this when you are deploying the **full Moose stack** as a long-lived server.

If you are running Moose OLAP without the runtime (library or serverless), apply migrations with [moose migrate (CLI)](/moosestack/migrate/apply-planned-migrations-cli) instead.

## How it works

The server treats migrations as a prerequisite for accepting traffic. It will not start ingestion APIs, consumption APIs, or streaming workers until the database schema matches the migration files in the deployment artifact.

| Feature | Description |
| :--- | :--- |
| **Automatic Execution** | Migrations run automatically when the `moose prod` command starts. |
| **Drift Protection** | The server validates the database state against `remote_state.json` before applying changes. |
| **Code Validation** | The server ensures the deployed code matches `local_infra_map.json` to prevent mismatches. |
| **Zero-Touch** | No separate CLI commands or CI/CD steps are required to apply migrations. |

## Command Reference

The migration logic is embedded within the production server start command.

```bash
moose prod
```

**Environment Variables:**
The server requires access to the ClickHouse database, typically configured via `moose.config.toml` or environment variables overridden at runtime.

## Execution Lifecycle

When `moose prod` starts, it performs the following sequence:

1.  **Load migrations:** Reads every committed migration file under `./migrations/` from the deployment artifact.
2.  **Check Code Consistency:** Verifies that the running application code matches the recorded infrastructure map. If not, it aborts to prevent deploying code that doesn't match the migrations.
3.  **Check Database Drift:** Connects to ClickHouse and compares the current schema against the recorded state. If drift is detected, it aborts.
4.  **Execute Migration:** Applies operations from any migration files that are not yet in the applied-migrations list.
5.  **Start Services:** Once migrations succeed, the Ingestion API, Consumption API, and Streaming workers are started.

## Failure Modes

| Condition | Outcome | Resolution |
| :--- | :--- | :--- |
| **Drift Detected** | Server fails to start. | Regenerate the migration against the current production DB and redeploy. |
| **Plan Mismatch** | Server fails to start. | Ensure the `migrations/` directory matches the code in your deployment artifact. |
| **Migration Error** | Server fails to start. | Fix the schema issue or migration file, then redeploy. See [Failed migrations](/moosestack/migrate/failed-migrations). |

<Callout type="info" title="Fiveonefour hosting">
If you are using Fiveonefour hosting, this process is handled automatically. The platform ensures that your application only becomes healthy once `moose prod` has successfully completed the migration phase.
</Callout>
