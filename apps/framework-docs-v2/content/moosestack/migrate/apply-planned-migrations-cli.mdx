# moose migrate (CLI)

`moose migrate` applies committed migration files against your database as a one-shot CLI command. Use it when you are running **Moose OLAP without the Moose runtime** — for example, embedding Moose OLAP as a library inside an existing Python or TypeScript application, or driving migrations from a CI/CD pipeline.

If you run the full Moose stack (`moose prod`), migrations are applied automatically on server startup — see [moose prod (Runtime)](/moosestack/migrate/apply-planned-migrations-service) instead.

## When to use

- **Library deployments** — Moose OLAP is imported into your application; there is no `moose prod` server to apply migrations on boot.
- **Serverless deployments** — no long-lived process exists to run migrations as part of startup.
- **CI/CD** — you want migrations applied as a discrete, reviewable step before deploying application code.

| Feature | Description |
| :--- | :--- |
| **Manual Control** | Migrations run only when you explicitly execute the command. |
| **CI/CD Integration** | Designed to run as a discrete step in deployment pipelines (e.g., GitHub Actions). |
| **Drift Protection** | Validates `remote_state.json` against the target database before execution. |
| **Direct Connection** | Connects directly to ClickHouse using a connection string. |

## Command Reference

```bash
moose migrate --clickhouse-url <CONNECTION_STRING>
```

### Options

| Option | Description | Required |
| :--- | :--- | :--- |
| `--clickhouse-url` | The full connection string to the target ClickHouse database (e.g., `clickhouse://user:pass@host:9440/db`). | Yes |
| `--redis-url` | Redis connection URL for state storage. Required when `state_config.storage = "redis"` in `moose.config.toml`. | No |
| `--validate` | Validate migration files without executing them. Checks delta sequence consistency and detects semantic conflicts. Does not require ClickHouse or Redis. | No |

## Execution Lifecycle

When `moose migrate` is executed:

1.  **Load migrations:** Reads every committed migration file under `./migrations/`.
2.  **Check applied state:** Compares against the applied-migrations list stored in state.
3.  **Check Database Drift:** Connects to the provided ClickHouse URL and compares the current schema against the recorded state.
4.  **Abort on Drift:** If the database state does not match the snapshot, the process exits with an error code.
5.  **Execute Migration:** Applies the operations from each unapplied migration file sequentially.
6.  **Report Success:** Exits with code 0 if all operations succeed.

## Failure Modes

| Condition | Outcome | Resolution |
| :--- | :--- | :--- |
| **Drift Detected** | Command fails (exit code 1). | Regenerate the migration against the current production DB and retry. |
| **Connection Error** | Command fails (exit code 1). | Check network connectivity and credentials in the connection string. |
| **SQL Error** | Command fails (exit code 1). | Fix the problematic operation in the migration file or the database state and retry. See [Failed migrations](/moosestack/migrate/failed-migrations). |

## CI/CD Example

This command is typically used in a deployment pipeline before updating the application code.

```yaml
# Example GitHub Actions step
- name: Apply Migrations
  run: moose migrate --clickhouse-url "$CLICKHOUSE_URL"
        env:
    CLICKHOUSE_URL: ${{ secrets.CLICKHOUSE_URL }}
```
