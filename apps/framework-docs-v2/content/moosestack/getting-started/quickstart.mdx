MooseStack is an open source, vertically-integrated coding agent harness for building on ClickHouse and realtime analytical infrastructure. It gives generalist coding agents (Claude Code, Cursor, Kiro, Codex, etc.) everything they need to build, iterate, and ship on analytical infrastructure — quickly, safely, and effectively.

This quickstart sets up the coding agent harness and gets you and your agent running against a local project with a live stack.

## Step 1: Install MooseStack

```bash filename="Terminal" copy
bash -i <(curl -fsSL https://fiveonefour.com/install.sh) moose
```

<Callout type="warning" title="Reload your shell configuration" compact={true}>
**Zsh (most macOS):**
```bash
source ~/.zshrc
```
**Bash (most Linux):**
```bash
source ~/.bashrc
```
Or close and reopen your terminal, then try again.
</Callout>

<Callout type="success" title="Checkpoint" icon="Check" compact={true}>
`moose --version` shows a version number. Do not proceed until this works.
</Callout>

If you see an error, check [Troubleshooting](#need-help) below.

`typescript-mcp` is a TypeScript monorepo with a Next.js chat frontend and a custom MCP server for querying your ClickHouse data. The following command connects it to the ClickHouse Playground:

```bash filename="Terminal" copy
moose harness init my-app typescript-mcp \

```

- **Coding agent** — defaults to auto-detected; pick Claude Code, Cursor, Kiro, Codex, or all

## Step 3: Start the harness

**Install dependencies:**

<LanguageTabs>
  <LanguageTabContent value="typescript">

```bash filename="Terminal" copy
cd my-app && npm install
```

  </LanguageTabContent>
  <LanguageTabContent value="python">

<Callout type="info" title="Recommended: create a virtual environment first" compact={true}>
```bash
python3 -m venv .venv && source .venv/bin/activate
```
</Callout>

```bash filename="Terminal" copy
cd my-app && pip install -r requirements.txt
```

  </LanguageTabContent>
</LanguageTabs>

**Start the dev server:**

```bash filename="Terminal" copy
moose dev
```

Wait for the `Started Webserver` message:

```txt
  Successfully started containers
     Validated clickhousedb-1 docker container
     Validated redpanda-1 docker container
  Successfully validated red panda cluster
     Validated temporal docker container
  Successfully ran local infrastructure
      Starting development mode
       Started Webserver.  👈 wait for this
```

<Callout type="success" title="Checkpoint" icon="Check" compact={true}>
The dev server is running. Keep this terminal open and move to Step 4.
</Callout>

## Need Help?

<ToggleBlock openText="Docker Not Running" closeText="Docker Not Running">
```bash filename="Terminal" copy
# macOS
open -a Docker

# Linux
sudo systemctl start docker

# Verify
docker ps
```

If Docker is running but you're still having issues:
```bash filename="Terminal" copy
docker system prune -a
```
</ToggleBlock>

<ToggleBlock openText="Outdated Language Version" closeText="Outdated Language Version">

**TypeScript — Node.js 20+ required:**
```bash filename="Terminal" copy
node -v

# Install Node 20+ with nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
nvm install 20 && nvm use 20
```

**Python — Python 3.12+ required:**
```bash filename="Terminal" copy
python3 --version

# Install Python 3.12+ with pyenv
curl https://pyenv.run | bash
pyenv install 3.12 && pyenv local 3.12
```
</ToggleBlock>

<ToggleBlock openText="Port Conflicts" closeText="Port Conflicts">

**Kill the conflicting process:**
```bash filename="Terminal" copy
lsof -i :4000
kill -9 <PID>
```

**Or use a different port** in `moose.config.toml`:
```toml filename="moose.config.toml" copy
[http_server_config]
port = 4001
```

<Callout type="info" title="Customizing all ports" compact={true}>
You can also customize ClickHouse, Redpanda, and Temporal ports. See the [Configuration Reference](/moosestack/configuration#mooseconfigtoml-reference).
</Callout>
</ToggleBlock>
