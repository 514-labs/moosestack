## How this guide works

This guide starts by installing a performance testing harness into your repo. Your agent uses the harness to run a controlled experiment that benchmarks different schema optimization strategies against the live query you want to optimize.

### The experiment

With the harness in place, the agent runs a controlled experiment using **preview branches** on [Fiveonefour hosting](/hosting). Each preview branch gets its own isolated ClickHouse database, so the only variable between runs is the schema change.

<BulletPointsCard
  title="What the agent does"
  bulletStyle="number"
  uppercase={false}
  bullets={[
    {
      title: "Freeze a baseline",
      description:

      description:
        "Each proposed schema change gets its own branch and its own preview database with the new layout applied.",
    },
    {
      title: "Benchmark every branch",
      description:
        "The agent runs the scaffolded benchmark package against every preview database. Same query, same thresholds, different table layout.",
    },
    {
      title: "Pick a winner",
      description:
        "The agent compares latency, `EXPLAIN` output, rows read, and memory usage across branches, then opens a PR for the best candidate.",
    },
  ]}
/>

Because every branch gets its own database, the comparison is clean. The baseline stays frozen and the candidates are isolated.

The experiment ends with a PR. It does not decide how to roll the change out to production. If the winner needs a phased release or a recovery plan, that planning happens after you approve the optimization.
