# Dev Approach

The Analytics Agent Harness has a lot of moving parts: ClickHouse, APIs, MCP tools, JWT auth, row-level security, observability, guardrails. You could wire it up by hand. Or you could give a coding agent a well-structured environment and let it do the bulk of the work.

The tutorial is designed for that second path. Every section has agent-ready prompts. The hard question isn't whether to use a coding agent — it's how to set that coding agent up to succeed.

The answer is the **Coding Agent Harness**.

## The Coding Agent Harness

The Coding Agent Harness is the build-time layer your coding agent works inside. It gives your coding agent live access to the running stack, real schema introspection, SQL validation, and domain-specific skills — so it can make accurate changes and verify them immediately instead of guessing.

The Analytics Agent Harness is what you're shipping. The Coding Agent Harness is what you build it with.

## The strategy: start locally, ship with confidence

The Coding Agent Harness runs the full Analytics Agent Harness on your machine. Your coding agent has a live ClickHouse instance, real schema introspection, and a running stack to validate against — before anything gets near production.

1. **Start locally** — the dev server runs the complete stack. Your coding agent works against real data, real schemas, real query results. No mocking, no guessing.
2. **Iterate fast** — hot-reloading, MCP-accessible logs, and the SQL Language Server let your coding agent make a change, see the result, and catch errors without manual inspection.
3. **Ship with confidence** — deploy to 514 hosting when you're ready. Preview environments per PR provision an isolated ClickHouse database per branch. Schema changes are validated before they hit production.

You're not guessing at whether something works. The Coding Agent Harness gives the coding agent a real environment to work against at every stage.
